# 집 보러 갔을 때 10분 현장 체크리스트

## 개발사항 정의서 v2.0 (전면 개정판)

> v1.0 대비 주요 변경: 체크박스 2단 → **항목 상태 4단계**, 진행률 단일지표 → **확인율 + 결과(점수·등급) 분리**,
> 시간순(도착 전/후) 카테고리 → **공간축(건물 밖 / 건물 안)**, 78문항 → **50문항**(핵심 31 + 선택 19),
> 순번 ID → **의미 기반 slug ID + schemaVersion**, "다음 이동" 버튼 제거 → **접기/펼치기 전용**.

# 1. 문서 목적

집을 직접 방문했을 때 사용자가 약 10분 안에 주요 상태를 확인하고 기록할 수 있는 모바일 우선 정적 웹 체크리스트를 정의한다. 서버 없이 브라우저(localStorage)에서 동작한다.

본 서비스는 다음 행동에 집중한다.

1. 방문한 집을 주소(또는 직접 입력)와 **별칭**으로 지정한다.
2. 현장에서 항목을 **양호 / 문제·우려 / 해당없음** 중 하나로 빠르게 표시한다.
3. 필요한 항목에 메모를 남긴다.
4. 입력 즉시 브라우저에 자동 저장된다.
5. 다시 접속했을 때 기존 기록을 불러와 수정한다.
6. 마지막에 **결과(점수·등급 + 문제 항목 요약)** 를 확인하고 최종 판단을 기록한다.

기능 범위는 **현장 관찰 기록과 그 요약**에 한정한다. 시세·등기·계약 조건 검토는 범위 밖이다.

# 2. 설계의 근본 원칙 — 두 지표의 분리

v1.0의 가장 큰 결함은 체크박스 하나가 **"확인했다"(진행 상태)** 와 **"문제없다"(품질 판단)** 라는 서로 다른 두 의미를 동시에 짊어졌다는 점이다. 이 경우 "문제가 있는 항목"은 체크할 수도 없고 안 할 수도 없어, 진행률과 품질이 동시에 왜곡된다.

v2.0은 이를 **입력 1개, 지표 2개**로 분리한다.

### 2.1 항목 상태 — 4단계

| 상태 | 표기 | 의미 | 확인율 분모 | 확인율 분자 | 점수 반영 |
|---|---|---|---|---|---|
| 양호 | ○ | 문장대로였다 | 포함 | 포함 | 감점 없음 |
| 문제·우려 | △ | 문장과 달랐거나 마음에 걸린다 | 포함 | 포함 | 등급별 감점 |
| 해당없음 | — | 이 집에는 해당 설비/조건이 없다 | **제외** | **제외** | 감점 없음 |
| 미응답 | (기본값) | 아직 보지 않았다 | 포함 | 제외 | 감점 없음 |

* 모든 항목의 기본값은 **미응답**이다. 자동으로 ○가 되지 않는다.
* 문항 문장은 전부 **"양호할 때 참이 되는 관찰 가능한 사실"** 로 통일한다. 따라서 ○/△의 의미가 문항마다 뒤집히지 않는다.

### 2.2 지표 1 — 확인율 (진행 안내 전용)

```text
확인율 = (양호 + 문제 + 해당없음) ÷ (전체 항목 − 해당없음) × 100
```

* 표기: `확인율 62% (31개 중 19개 응답)`
* **무채색(회색)으로만 표시한다.** 초록/빨강 등 가치 색상을 쓰지 않는다.


### 2.3 지표 2 — 결과 (판단 전용)

문제(△)로 표시된 항목만으로 계산한 **점수·등급 + 문제 항목 목록**이다. 색상(초록/노랑/주황/빨강)은 오직 이쪽에만 사용한다. 상세는 [01_체크리스트_정보구조.md](./01_체크리스트_정보구조.md) §결과 참고.

# 3. 핵심 사용자 시나리오

## Scenario 01. 새로운 집 점검

1. 접속 → `새 집 체크하기`.
2. 주소를 검색해 선택하거나, 검색이 안 되면 **직접 입력**한다.
3. **별칭**을 입력한다. (예: `302호`, `역세권 반지하`)
4. 방문일이 오늘로 자동 입력된다. 나머지 기본 정보는 선택 입력.
5. `건물 밖` 대분류부터 항목을 ○ / △ / — 로 표시한다.
6. △로 표시하면 그 자리에서 메모 입력창이 펼쳐진다.
7. `건물 안`으로 내려가며 계속 표시한다.
8. 확인율 70%를 넘는 순간 하단 결과 영역에 점수·등급이 나타난다.
9. 결과 요약에서 △ 항목이 자동 나열된 것을 확인한다.
10. 최종 판단(계약 추진 / 보류 / 탈락)을 고르고 한 줄 평가를 남긴다.
11. 모든 입력은 자동 저장된다.

## Scenario 02. 같은 건물 다른 호수 연달아 보기

1. 302호 점검을 마친다.
2. `새 집 체크하기` → 같은 주소를 선택하고 별칭만 `501호`로 입력한다.
3. 저장 목록에서 두 기록이 **별칭으로 구분되어** 보인다.

## Scenario 03. 이전 기록 확인·수정

1. 재접속 → `최근 체크한 집` 목록에서 하나를 선택한다.
2. 기존 상태·메모·결과가 그대로 복원된다.
3. 수정하면 즉시 자동 저장된다.

# 4. 본 버전에서 제외하는 기능

* 회원가입 / 로그인 / 서버 DB / 클라우드 동기화
* 다른 사용자와 공유
* PDF 내보내기
* 이미지 촬영 / 사진 첨부
* 지도 표시 / GPS 기반 현재 위치
* 주변 편의시설 자동 검색
* 실거래가 · 전세가 조회
* 등기부 · 건축물대장 조회
* 부동산 위험도 분석 / AI 추천
* **매물 비교 분석** (여러 매물을 나란히 놓고 비교하는 화면 — 계속 제외)
* 중개사 연결
* 계약 체크리스트

> v1.0에서 제외 목록에 있던 **`점수화`와 `매물 자동 평가`는 본 버전에 포함**되었으므로 목록에서 삭제했다([01_체크리스트_정보구조.md](./01_체크리스트_정보구조.md) §결과 참고).

목적은 어디까지나 **"현장에서 집을 보면서 빠르게 기록하고, 그 기록으로 판단을 돕는 것"** 에 한정한다.

# 5. MVP 완료 조건

## 매물 지정

- [ ] 주소를 검색해 선택할 수 있다.
- [ ] 검색이 실패하거나 오프라인이어도 **주소를 직접 입력해 점검을 시작할 수 있다.**
- [ ] 별칭을 입력할 수 있고, 목록에서 별칭으로 기록이 구분된다.
- [ ] 주소를 수정해도 **기존 체크 내용이 항상 유지된다.** 새 기록은 오직 `새 집 체크하기`(초기 진입)로만 시작한다.

## 체크리스트

- [ ] 건물 밖 / 건물 안 2개 대분류 아래 9개 카테고리가 표시된다.
- [ ] 핵심 31문항이 기본 노출되고, 선택 19문항이 `+ 더 볼 항목`으로 펼쳐진다.
- [ ] 각 항목을 **양호 / 문제 / 해당없음**으로 표시할 수 있고, 같은 버튼 재클릭 시 미응답으로 돌아간다.
- [ ] `해당없음`은 에어컨·붙박이장·엘리베이터·방충망·주차·세탁기 자리 항목에서 선택 가능하다.
- [ ] 문제(△) 선택 시 항목별 메모 입력창이 펼쳐진다.
- [ ] 카테고리를 **접고 펼칠 수 있다.**
- [ ] **카테고리 하단에 "다음" 이동 버튼이 존재하지 않는다.**
- [ ] 카테고리별 메모를 입력할 수 있다.
- [ ] 소음 정도를 선택할 수 있고, `거주하기 어려운 수준`이 치명 1건으로 계산된다.

## 지표

- [ ] 확인율이 무채색으로 표시되고, "좋고 나쁨과 무관"하다는 안내가 함께 보인다.
- [ ] 확인율 계산에서 `해당없음`이 분모에서 제외된다.
- [ ] 카테고리 헤더에 `응답 n/m · 문제 k`가 표시된다.

## 결과

- [ ] 감점제 점수(치명 −15 / 중요 −6 / 참고 −2)가 계산된다.
- [ ] 양호 / 보통 / 주의 / 위험 4등급이 [01_체크리스트_정보구조.md](./01_체크리스트_정보구조.md) §12.3절 조건대로 판정된다(치명 건수 우선).
- [ ] **확인율 60% 미만이면 점수·등급 대신 "아직 판단하기 이릅니다" 안내가 표시된다.**
- [ ] 점수 옆에 면책 문구가 표시된다.
- [ ] `문제로 표시한 항목` 목록이 △ 항목에서 **자동 생성**된다(사용자 재선택 없음).
- [ ] 목록의 항목을 누르면 해당 체크 항목으로 이동한다.
- [ ] `좋았던 점`을 0~3개 가변으로 입력할 수 있다.

## 중개사 질문

- [ ] 8개 질문에 답변을 입력할 수 있다.
- [ ] 이 섹션은 확인율·점수에 영향을 주지 않는다.

## 최종 판단

- [ ] 계약 추진 / 보류 / 탈락 중 하나를 선택할 수 있다.
- [ ] `조건 협의 필요`를 최종 판단과 **독립적으로** 체크할 수 있다.
- [ ] 한 줄 평가를 입력할 수 있다.

## 저장

- [ ] 작성 내용이 자동 저장되고 저장 상태가 표시된다.
- [ ] 수동 저장이 가능하다.
- [ ] 새로고침 후에도 내용과 접힘 상태가 유지된다.
- [ ] 새 기록을 만들 수 있고, 기존 기록을 불러오고 수정하고 삭제할 수 있다.
- [ ] **`체크 결과 복사`로 텍스트 백업을 만들 수 있다.**
- [ ] **JSON 내보내기 / 가져오기가 동작한다.**
- [ ] `schemaVersion`이 저장되고, 낮은 버전 데이터가 로드 시 마이그레이션된다.

# 6. 개발 우선순위

### P0 — 반드시 구현

* 주소 검색 / 선택 **+ 직접 입력 폴백**
* 매물 별칭
* 기본 매물 정보
* 전체 50문항 렌더링 (핵심 31 기본 노출 / 선택 19 더보기)
* 항목 4단계 상태 입력
* 항목별 · 카테고리별 메모
* 확인율(무채색) 계산·표시
* 점수 / 등급 계산 + **확인율 60% 미만 표시 차단**
* 문제 항목 자동 요약
* 중개사 질문 섹션
* 최종 판단 · 한 줄 평가
* localStorage 저장 / 불러오기 (`schemaVersion` 포함)
* 카테고리 접기/펼치기
* 모바일 대응

### P1 — 사용성 개선

* **텍스트로 복사 / JSON 내보내기·가져오기** (저장 소실 대비, 사실상 필수)
* 자동 저장 상태 표시
* 카테고리 헤더 요약(`응답 n/m · 문제 k`)
* `아직 확인 안 한 항목 보기` (미응답 카테고리 일괄 펼침)
* 결과 항목 → 체크리스트 스크롤 이동
* 좋았던 점 가변 입력
* 신규 기록 생성 / 기록 삭제
* 저장 목록 카드에 점수·확인율 표시

### 제거된 항목 (v1.0 P1)

* ~~이전 / 다음 이동~~ — 접기/펼치기로 대체, 전면 삭제

P0와 P1까지 구현하면 본 문서가 정의한 기능 범위는 완료된 것으로 본다.
