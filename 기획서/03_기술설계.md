# 1. 주소 검색 — 리스크와 폴백

본 서비스는 **서버가 없는 정적 페이지**다. 국내 주소 API(도로명주소 open API, 카카오/네이버 지도)는 대부분 **서비스 도메인 사전 등록** 또는 **서버 프록시**를 요구하고, 키가 클라이언트에 노출된다. 또한 현장은 지하·엘리베이터 등 **통신이 끊기는 상황**이 흔하다.

따라서 다음을 **필수 요구사항**으로 정의한다.

1. 주소 검색은 `searchAddress(keyword)` 단일 함수로 격리하고, 제공자 교체가 체크리스트 로직에 영향을 주지 않게 한다.
2. **주소 직접 입력 폴백을 항상 제공한다.** 검색창 아래에 `주소를 직접 입력할게요` 진입점을 상시 노출한다. 검색 실패·오프라인·API 미설정 상태에서도 점검을 시작할 수 있어야 한다.
3. 검색 실패 시 안내: `주소를 불러오지 못했습니다. 직접 입력해도 점검은 그대로 진행됩니다.`
4. 검색 결과의 저장 형식과 직접 입력의 저장 형식은 동일하다.

```javascript
{ buildingName: "", roadAddress: "", jibunAddress: "", isManualInput: false }
```

UI 흐름(검색창, 검색결과 리스트, 선택 동작)과 매물 별칭·주소 변경 UX는 [02_UI_UX설계.md](./02_UI_UX설계.md) §매물 지정 참고.

# 2. 데이터 구조

## 2.1 문항 ID 설계 원칙

v1.0은 `item01`, `item02` 같은 **순번 ID**를 사용했다. 이 방식은 문항을 하나 삭제하면 그 뒤 모든 항목의 의미가 한 칸씩 밀려, 이미 저장된 기록이 **조용히 잘못된 항목에 매핑된다.**

v2.0은 다음을 강제한다.

1. 모든 문항은 **의미 기반 slug ID**를 갖는다. (실제 채택 ID는 [01_체크리스트_정보구조.md](./01_체크리스트_정보구조.md) §전체 50문항 참조: `mold_black`, `hotwater_kitchen`, `drain_bath` …)
2. ID는 **한 번 배포되면 절대 재사용하지 않는다.** 문항을 삭제해도 그 ID는 영구 폐기한다.
3. 저장 데이터는 **카테고리 중첩 없이 항목 ID를 평면 키로** 갖는다. 카테고리 소속은 코드(`checklist-data.js`)의 정의에만 존재하므로, 카테고리를 재편해도 저장 데이터는 깨지지 않는다.
4. 최상위에 **`schemaVersion`** 을 둔다. 로드 시 버전이 낮으면 마이그레이션 함수를 태우고, 알 수 없는 ID는 버리지 않고 `unknownItems`에 보존한다.

# 3. 저장 기능

## 3.1 저장 방식과 그 한계

1차 버전은 서버 없이 `localStorage`를 사용한다. 다만 다음 상황에서 **데이터가 소실될 수 있다.**

* iOS Safari의 사생활 보호 모드 / 7일 이상 미사용 시 스토리지 정리
* 브라우저 데이터·캐시 삭제
* 기기 변경, 다른 브라우저로 접속

따라서 **내보내기 기능을 P1 필수로 정의한다.**

## 3.2 내보내기 (P1 필수)

### 텍스트로 복사

`[체크 결과 복사]` 버튼. 클립보드에 사람이 읽을 수 있는 요약을 넣는다. 카카오톡·메모앱에 그대로 붙여넣어 보관할 수 있다.

```text
성수 OO빌라 302호
서울특별시 성동구 OO로 00
2026-09-03 방문 · 확인율 87%

결과: 78점 (보통)
치명적인 문제는 없지만 아쉬운 점이 있습니다.

문제로 표시한 항목 (5)
- [중요] 창틀과 벽 모서리에 물이 고였던 자국… (안방 창틀 아래 벽지 들뜸)
- [중요] 옆집이나 위층의 생활음이 들리지 않는다.
- [중요] 방마다 콘센트가 2구 이상 있다.
- [참고] 계단과 복도에 쓰레기나 개인 물건이 쌓여 있지 않다.
- [참고] 방문과 욕실문이 바닥에 끌리지 않고 여닫힌다.

중개사 답변
- 인터넷: SK 회선 들어와 있음
- 관리비: 수도 포함, 난방 별도
- 반려동물: 불가
- 입주가능일: 10월 초

최종 판단: 보류 (조건 협의 필요 — 벽지 보수 요청)
한 줄 평가: 채광과 위치는 좋지만 위층 발소리가 계속 들렸다.
```

클립보드 API 실패 시 `<textarea>`에 내용을 띄우고 직접 복사하도록 안내한다.

### JSON 내보내기 / 가져오기

`[전체 기록 내보내기]` — 저장된 모든 기록을 `.json` 파일로 다운로드(Blob + `<a download>`).
`[기록 가져오기]` — `<input type="file">` 로 읽어 `schemaVersion`을 확인 후 병합한다. 같은 `id`는 `updatedAt`이 최신인 쪽을 남긴다.

## 3.3 자동 저장

| 대상 | 시점 |
|---|---|
| 항목 상태(○/△/—) | 변경 즉시 |
| 라디오 / 체크박스 | 변경 즉시 |
| 텍스트 입력 · textarea | 입력 후 500ms debounce |

상태 표시(상단 고정, 작은 텍스트):

```text
저장 중...      →      ✓ 저장됨      /      저장하지 못했습니다.
```

저장 실패(용량 초과, 사생활 보호 모드 등) 시:

```text
브라우저에 저장하지 못했습니다.
[체크 결과 복사]로 내용을 백업해 주세요.
```

## 3.4 수동 저장

페이지 하단 `[현재 내용 저장]`. 클릭 시 전체 데이터를 저장하고 Toast로 `체크리스트가 저장되었습니다.` 를 짧게 표시한다.

## 3.5 목록 · 신규 · 삭제

### 최근 체크한 집

주소 영역 하단 진입점. 카드 형태로 표시한다.

```text
302호                          78점 · 보통
성수 OO빌라 · 서울 성동구 OO로 00
2026.09.03 · 확인율 87%
```

* **별칭을 가장 크게** 표시한다(같은 주소 구분 목적).
* 확인율 60% 미만이면 점수 자리에 `점검 중`으로 표시한다.
* 별도의 매물 관리 페이지는 만들지 않는다.

### 새 집 체크하기

신규 기록 Object를 생성하고 `currentInspectionId`를 교체한다. 기존 기록은 삭제하지 않는다.

### 기록 삭제

```text
이 체크 기록을 삭제하시겠습니까?
삭제된 기록은 복구할 수 없습니다.

[취소] [삭제]
```

### 새로고침 처리

초기 로드 시 `currentInspectionId`를 확인해 해당 기록을 복원한다. 접힘/펼침 상태(`ui`)도 함께 복원한다.

## 3.6 입력 검증

과도한 Validation은 적용하지 않는다.

* 주소·별칭이 모두 비어 있는 상태로 저장 시: `이 집을 뭐라고 부를까요? 주소를 검색하거나 별칭을 입력해 주세요.`
* 방문일, 금액: 필수 아님. 금액은 자유 형식(`3억`, `3억 5천`, `350,000,000` 모두 허용).
