# 1. 문항 문장 작성 규칙

v1.0 문항은 `심하지 않다`, `지나치게 ~않다`, `적절하다`, `의심스럽지 않다` 같은 **이중부정 + 모호한 정도부사 + 판단어**가 많아 두 사람이 같은 집을 보고 다른 답을 하게 만들었다.

v2.0 문항은 다음을 지킨다.

* **관찰 가능한 사실**로 쓴다. (`분전반이 노후돼 보이지 않는다` → 삭제, 일반인이 판정 불가)
* 판단 기준을 문장에 넣는다. (`온수가 정상적으로 나온다` → `틀고 3분 안에 뜨거운 물이 나온다`)
* 이중부정을 피한다. (`의심스럽지 않다` → `한 부분만 새것처럼 다시 도배된 곳이 없다`)
* 한 문항에 한 가지만 묻는다.
* 모든 문항은 **"양호할 때 참"** 인 방향으로 통일한다.
* `~을 확인했다` 같은 **할 일(task)형 문장은 체크리스트에 쓰지 않는다.** (§3 중개사에게 물어볼 것 으로 이동)

| 대분류 | 카테고리 | 핵심 | 선택 | 합계 |
|---|---|---:|---:|---:|
| 건물 밖 | A. 건물·공용부 | 2 | 3 | 5 |
| 건물 밖 | B. 주차·주변환경·접근성 | 3 | 2 | 5 |
| 건물 안 | C. 첫인상 | 3 | 2 | 5 |
| 건물 안 | D. 벽·천장·창문 | 5 | 2 | 7 |
| 건물 안 | E. 소음 | 2 | 1 | 3 |
| 건물 안 | F. 주방 | 4 | 1 | 5 |
| 건물 안 | G. 욕실·화장실 | 6 | 2 | 8 |
| 건물 안 | H. 냉난방·전기 | 3 | 3 | 6 |
| 건물 안 | I. 문·수납·공간 | 3 | 3 | 6 |

등급별: 치명 10 / 중요 25 / 참고 15 = 50

# 3. 중개사에게 물어볼 것 (질문 목록 — 체크리스트 아님)

현장에서 **눈으로 확인할 수 없는 정보**는 체크리스트에서 분리한다. 이 섹션은 상태(○/△/—)를 갖지 않으며, **확인율과 점수 계산에서 완전히 제외된다.**

UI는 `질문 문장 + 답변 입력창(1줄)` 형태다. 답을 적지 않아도 무방하다.

| ID | 질문 |
|---|---|
| `q_internet` | 인터넷 회선이 들어와 있나요? 어느 통신사인가요? |
| `q_management_fee` | 관리비에 무엇이 포함되나요? (수도/난방/인터넷/청소비) |
| `q_repair_history` | 최근 도배·장판·보일러·전기 설비 수리나 교체 이력이 있나요? |
| `q_parking_fee` | 주차는 세대당 몇 대이고 비용은 얼마인가요? |
| `q_pet` | 반려동물을 키울 수 있나요? |
| `q_move_in` | 입주 가능일이 언제인가요? |
| `q_trash_rule` | 음식물·일반 쓰레기는 언제 어디에 배출하나요? |
| `q_etc` | 그 밖에 물어본 것 |

총 **8개 질문**.

> v1.0에서 이곳으로 옮겨온 항목: `인터넷 설치에 문제가 없다`(현장 확인 불가), `음식물쓰레기 배출 장소를 확인했다`(유일한 '확인했다' 할 일형 문장이라 체크 의미가 또 갈라졌음), `분전반이 노후돼 보이지 않는다`(일반인 판정 불가).

# 4. 결과 — 점수와 등급

> v1.0에서 "제외 기능"으로 두었던 **점수화 / 매물 자동 평가는 본 버전에 포함한다.**
> 단 **매물 비교 분석**(여러 매물을 나란히 비교하는 화면)은 계속 제외한다.

## 4.1 항목 등급 3단계

| 등급 | 뜻 | 대표 항목 |
|---|---|---|
| **치명 (Critical)** | 거주 자체가 어렵거나 수리 비용·분쟁 위험이 큰 문제 | 누수 흔적, 검은 곰팡이, 온수 불량, 수압 불량, 배수 불량, 보일러 불량, 현관문 잠금 불량, 거주 곤란 수준의 소음 |
| **중요 (Major)** | 살면서 반복적으로 불편하지만 협의·보수로 완화 가능 | 결로 흔적, 환기 불가, 채광 부족, 환풍기 불량, 콘센트 부족, 창문 개폐·잠금, 방범 |
| **참고 (Minor)** | 취향·편의 수준의 문제 | 수납 크기, 생활시설 접근성, 공용부 청결, 언덕, 문 끌림 |

## 4.2 점수 계산식 — 감점제

```text
점수 = 100
     − (치명 문제 건수 × 15)
     − (중요 문제 건수 × 6)
     − (참고 문제 건수 × 2)

하한 0점.
```

* **문제(△)로 표시한 항목만 감점한다.** 미응답과 양호(○)는 감점하지 않는다.
* **`해당없음(—)`은 감점과 분모 양쪽에서 모두 제외한다.**
* **선택 19문항도 응답했다면 동일한 규칙으로 감점에 포함한다.** 펼치지 않은 항목은 미응답이므로 영향이 없다.
* **소음 정도** 라디오에서 `거주하기 어려운 수준`을 선택하면 **치명 1건**을 추가 계산한다(−15).

## 4.3 등급 구간

| 등급 | 조건 | 색 | 문구 |
|---|---|---|---|
| **양호** | 85점 이상 **AND** 치명 0건 | 초록 | `큰 결격 사유가 발견되지 않았습니다. 계약 검토를 진행해도 좋습니다.` |
| **보통** | 70~84점 **AND** 치명 0건 | 노랑 | `치명적인 문제는 없지만 아쉬운 점이 있습니다. 조건 협의 여지를 확인해 보세요.` |
| **주의** | 50~69점 **OR** 치명 1건 | 주황 | `거주 후 불편이 예상됩니다. 다른 집과 비교해 보시길 권합니다.` |
| **위험** | 50점 미만 **OR** 치명 2건 이상 | 빨강 | `계약 전 반드시 재확인이 필요합니다.` |

판정 순서는 위험 → 주의 → 보통 → 양호로, **더 낮은 등급 조건이 먼저 적중하면 그 등급으로 확정한다.** (예: 92점이어도 치명 1건이면 `주의`)

## 4.4 필수 안전장치 — 표본 부족 시 점수 미표시

**핵심 31문항 기준 확인율이 60% 미만이면 점수와 등급을 표시하지 않는다.** 몇 개만 보고 매긴 점수는 사용자를 오도한다.

```text
아직 판단하기 이릅니다 (확인율 42%)

6개 항목을 더 확인해 주세요. (핵심 31개 중 13개 응답)
확인율 60%를 넘으면 점수와 등급을 보여드립니다.

[아직 확인 안 한 항목 보기]
```

* `아직 확인 안 한 항목 보기`는 미응답 항목이 있는 카테고리를 모두 펼친다.
* 확인율이 60%를 넘는 순간 점수 영역이 나타난다.

결과 화면의 실제 구성(ASCII 목업)은 [02_UI_UX설계.md](./02_UI_UX설계.md) §결과 화면 구성 참고.

## 4.5 "추가 확인 필요" 목록의 자동 생성

v1.0은 사용자가 손으로 다시 고르는 다중선택 체크박스였고, 체크리스트와 매핑되지도 않았다(주차·수리 여부는 체크리스트에 존재하지도 않았다).

v2.0에서 이 섹션은 **별도 입력이 아니라, △로 표시된 항목에서 자동 생성되는 요약**이다(`문제로 표시한 항목` 블록, [02_UI_UX설계.md](./02_UI_UX설계.md) §결과 화면 구성 참고). 사용자가 다시 고를 필요가 없다.

* 정렬: 치명 → 중요 → 참고, 그 안에서는 카테고리 순.
* 각 줄에 해당 항목의 메모가 있으면 함께 표시한다.
* 항목을 누르면 체크리스트의 해당 항목으로 스크롤 이동한다(카테고리가 접혀 있으면 자동으로 펼친다).
* 문제가 0건이면: `문제로 표시한 항목이 없습니다.`

## 4.6 장점 / 단점 입력의 처리

v1.0은 장점 3칸·단점 3칸을 고정 제공했다. 좋은 집은 단점을, 나쁜 집은 장점을 억지로 채우게 되고, 단점 입력은 §4.5의 자동 요약과 정면으로 중복된다.

**결론: 단점 입력 3칸은 삭제한다.** 단점은 `문제로 표시한 항목` 자동 요약이 대신한다.

**장점만 가변 입력으로 남긴다.**

```text
좋았던 점 (선택)

  [                                    ]
  + 추가          ← 최대 3개까지
```

* 기본 1칸, `+ 추가`로 최대 3칸까지 늘어난다.
* 체크리스트는 "문제 없음"만 기록할 뿐 "특별히 좋았던 점"은 담지 못하므로 이 입력만 남긴다.

# 5. 최종 판단

## 5.1 단일 축 3지선다

v1.0의 `다른 집과 비교 후 결정`과 `조건 협의가 가능하면 검토`는 **동시에 참일 수 있어** 단일선택 라디오로 부적절했다. v2.0은 "이 집을 어떻게 할 것인가"라는 **하나의 축**으로만 묻는다. UI 렌더링 예시(라디오 목업)는 [02_UI_UX설계.md](./02_UI_UX설계.md) §최종 판단 참고.

## 5.2 협의 필요 여부 (별도 체크)

배타적 축이 아니므로 라디오에서 분리해 독립 체크박스로 둔다. UI 렌더링 예시는 [02_UI_UX설계.md](./02_UI_UX설계.md) §최종 판단 참고.

## 5.3 한 줄 평가

이 집에 대한 인상을 짧은 문장으로 남기는 자유 입력이다. UI 렌더링 예시는 [02_UI_UX설계.md](./02_UI_UX설계.md) §최종 판단 참고.

최종 판단·협의 여부·한 줄 평가는 확인율과 점수에 반영하지 않는다.

# 6. 확인 현황 — 계산식과 정의

체크리스트 상단에 고정 표시한다. 계산 기준은 §2.2절(§00_개요.md §설계의 근본 원칙)과 같다.

* **핵심 31문항 기준**으로 계산한다. 선택 19문항은 응답한 것만 분자·분모에 추가로 포함한다(펼치지 않았다면 아예 계산에서 빠진다).
* 최종 판단, 메모, 중개사 질문 목록은 확인율에 반영하지 않는다.

화면 표시 방식(무채색, 보조 문구 배치 등)은 [02_UI_UX설계.md](./02_UI_UX설계.md) §확인 현황 참고.
